# 架构与可靠性设计

当前方案：Rust 原生连续文档界面、隐式语法范围、本地 JSON 文件持久化。用户于 2026-10-22 确认去掉 SQLite；本文件已替换旧表结构设计，详细提交规则见 [文件存储设计](12-file-storage-design.md)。历史实现与测试仅记录在相应步骤报告中。

## 模块

| 模块 | 职责 |
| --- | --- |
| `main.rs`、`app.rs` | 启动、生命周期、菜单动作、工作区协调、错误呈现 |
| `model/` | 工作区与语法范围、稳定 UUID、顺序、最近关闭、不变量及连续文本编辑映射；不依赖 GUI |
| `ui/` | 每工作区一个 TextEdit、复合着色布局、选区、撤销元数据、标签、查找、状态栏及集中中文文案 |
| `editor/` | syntect 只读高亮、纯文本剪贴板、查找匹配和编辑命令适配 |
| `persistence/store.rs` | 工作区 JSON、提交清单、校验、单实例锁、原子替换、完整备份、归档恢复及旧版本清理 |
| `persistence/autosave.rs` | revision、防抖、最长等待和失败重试；不依赖 UI 或具体存储 |
| `file_io/` | 严格 UTF-8/UTF-16 编解码、关联文件指纹检查、分阶段写回及导出 |
| `settings/` | 默认值、偏好和操作系统标准应用数据目录 |

依赖版本由 Cargo.toml/Cargo.lock 固定。应用主体不链接 SQLite，不需要数据库服务、账号或网络。

## 状态边界

Workspace 对应一个 Tab；EditorRegion 是后台语法范围，保存文本、语言、归属、文件关联及时间等。工作区内列表顺序就是文档文本顺序；显示时不插入标题或分隔符。每个范围独立着色，编辑时整体使用一个文档光标、选区和文本撤销栈。高度字段保留旧数据兼容，但不再显示独立面板。

UI 的查找词、弹窗、焦点、选区及撤销缓存不进入文本。活动工作区和语法范围、关闭状态、标题编号、主题、字号与窗口大小持久化。高亮不写入文本。复制只写纯文本。

## 文件布局与提交

`session.json` 包含格式版本、活动工作区、标签顺序、编号和外观偏好，按顺序引用 `workspaces/<UUID>-<SHA256>.json`。工作区文件包含原始文本及全部区域数据，内容寻址，未变更的工作区复用既有文件。

保存先检查模型与偏好，再写所有变化的工作区版本并同步文件，最后原子替换并同步清单。清单是唯一提交点；此前的中断留下旧提交及可清理的孤立文件，不会让新旧标签状态混杂。没有文件写回成功之前就显示“已保存”的旁路。

`std::fs::File` 跨平台独占锁防止两个应用同时写入。原子替换通过 tempfile，Unix 另同步父目录；Windows 目前没有目录同步的 std 实现，不承诺硬件断电时绝对持久。

## 自动保存与维护

变化增加 revision；400ms 防抖，连续输入最长约 2s 提交，失败约 3s 重试。失败持续显示，内存内容保留且可继续编辑、复制恢复 JSON 或导出。正常退出再次保存并备份，不要求未命名 Tab 逐个另存为。未提交输入在强杀时仍可能丢失。

提交后清理不再被清单引用的已发布工作区文件，备份保存独立完整快照，因此不依赖这些旧版本。清理或备份失败与内容提交失败分别显示，不把已提交内容错误标记为未保存。

## 备份与恢复

完整备份写入 `backups/backup-*.json`，版本化并验证后发布，最多每 60s 一次，退出强制备份，保留 3 份。启动验证清单版本、合法文件引用、SHA-256、模型关系及偏好。

损坏、缺失引用或缺失清单时，先将现存清单和工作区文件复制同步到 `recovery/archive-*/`，再选择最新有效备份，最后通过同一提交路径恢复。归档前不删除原件，恢复前后中断都可以再次启动重试。未知新版本、目录权限和 I/O 错误不当作可恢复损坏处理。无有效备份时保留原数据并在独立恢复工作区继续编辑。

## 非阻塞启动

应用只处理自己的 JSON 文件，不探测其他格式、不自动导入其他文件。主工作区打不开时保留错误作为顶部通知，使用独立恢复目录继续编辑和自动保存；恢复目录也全部不可用时仍打开内存编辑器，明确提示尚未持久化。主目录和当前恢复目录均受文件打开/导出保护。

恢复目录优先使用主数据目录旁追加 `.recovery` 的稳定路径，其次是用户缓存和系统临时目录中的隔离路径；锁冲突时另开唯一目录，避免覆盖另一个实例。保存位置可在通知详情中查看，恢复内容不自动合并到主目录。无有效备份不会覆盖损坏的主文件，也不会阻止编辑窗口启动。

## 真实文件与性能边界

工作区自动保存与磁盘真实文件分离。只有显式保存才写回原路径；从同一文件拆分的语法范围按顺序合并写回，避免截断。写入前检查外部修改，失败保留本地副本；导出仍是当前语法范围的 UTF-8 副本。

同步高亮对每个范围超过 256KiB 或单行超过 16KiB 暂停着色，保留实际语言及全部文本。约 1MiB 的实测结果有明确平台和构建条件，不能推导无限文件支持。窗口渲染、文本布局与持久化是不同的内存/性能来源，去除 SQLite 不等于解决图形资源占用。
